# 중고차 의심 차량 예측 프로젝트

## 프로젝트 개요

이 프로젝트는 Kaggle의 미국 중고차 데이터를 활용해, 판매 중인 차량이 사고 이력·프레임 손상·salvage 이력·도난 이력 등으로 인해 구매자가 추가 확인해야 할 가능성이 있는지 예측하는 데이터 분석 프로젝트입니다.

서비스 기획자의 관점에서 이 분석은 단순히 모델 성능을 확인하는 실험이 아니라, 중고차 거래 서비스에서 사용자가 위험 가능성이 있는 매물을 더 빠르게 인지하도록 돕는 기능을 설계하기 위한 과정입니다. 예를 들어 매물 상세 페이지에서 “주의 확인 필요” 배지를 보여주거나, 사고 이력 조회를 유도하거나, 운영자가 검수해야 할 매물의 우선순위를 정하는 데 활용할 수 있습니다.

데이터 출처: https://www.kaggle.com/datasets/ananaymital/us-used-cars-dataset

## 분석 목표

이 프로젝트의 목표는 중고차 매물의 주요 정보만으로 의심 차량 여부를 예측하는 것입니다.

원본 데이터에는 서비스에서 바로 사용할 수 있는 단일 “의심 차량” 라벨이 없기 때문에, 사고 이력과 위험 이력 관련 컬럼을 조합해 `suspected`라는 타겟을 새로 만들었습니다. 이후 이 타겟을 기준으로 모델을 학습시켜, 신규 매물이 들어왔을 때 의심 확률(`suspected_prob`)과 최종 예측값(`suspected_pred`)을 제공할 수 있도록 구성했습니다.

즉, 최종 목적은 모델 자체를 만드는 것이 아니라, 중고차 플랫폼에서 구매자의 판단을 보조하는 위험 신호 기능을 만드는 것입니다.

## 전체 분석 흐름

### 1. 원천 데이터 구조 파악

먼저 약 300만 건, 66개 컬럼으로 구성된 원본 데이터를 불러와 컬럼 구조, 데이터 타입, 결측치, 주요 변수의 의미를 확인했습니다.

중고차 데이터는 차량 스펙, 판매자 정보, 가격, 사고 이력, 인증 여부 등 다양한 정보가 섞여 있기 때문에, 모든 컬럼을 그대로 사용하는 것보다 서비스 목적에 맞는 정보를 선별하는 과정이 필요했습니다.

### 2. 피처와 타겟 후보 선정

모델 입력값으로 사용할 피처는 다음 기준으로 선정했습니다.

- 사용 이력 및 상태: `mileage`, `owner_count`, `daysonmarket`
- 가격 및 시장 반응: `price`, `savings_amount`
- 차량 구조 및 성능: `engine_type`, `fuel_type`, `body_type`, `wheel_system`, `transmission`
- 판매 환경: `city`, `seller_rating`, `franchise_dealer`

타겟 후보로는 차량 위험 이력과 직접 관련된 `has_accidents`, `frame_damaged`, `salvage`, `theft_title`을 확인했습니다.

### 3. 불필요하거나 활용이 어려운 컬럼 제거

원본 데이터의 모든 컬럼을 사용하지 않은 이유는 모델 복잡도를 줄이고, 서비스에서 설명 가능한 판단 기준을 만들기 위해서입니다.

`engine_cylinders`는 `engine_type`과 의미가 중복될 수 있어 제거했습니다. `horsepower`, `engine_displacement`는 결측과 품질 문제가 있어 안정적인 학습에 부적합하다고 판단했습니다. `dealer_zip`은 `city`와 위치 정보가 중복되고 너무 세분화될 수 있어 제외했습니다.

또한 `description`, `major_options` 같은 텍스트 컬럼은 별도의 자연어 처리 과정이 필요합니다. 이번 프로젝트의 목적은 구조화된 매물 정보만으로 의심 차량 가능성을 예측하는 것이므로, 텍스트 분석은 향후 고도화 범위로 남기고 제외했습니다.

### 4. 결측치 및 데이터 타입 정리

`has_accidents`, `frame_damaged`, `salvage`, `theft_title`은 결측값을 `False`로 처리했습니다. 해당 컬럼들은 위험 이력이 명시되는 성격이 강하므로, 값이 없으면 위험 이력이 표시되지 않은 것으로 해석했습니다.

수치형 변수인 `mileage`, `seller_rating`은 중앙값으로 결측치를 채웠습니다. 중고차 데이터는 주행거리나 가격처럼 극단값이 발생하기 쉬운 데이터이므로 평균보다 중앙값이 더 안정적인 기준이 될 수 있습니다.

`owner_count`는 결측 여부 자체가 데이터 신뢰도와 관련된 신호일 수 있어 `owner_count_missing` 컬럼을 만들고, 결측값은 `-1`로 처리했습니다.

### 5. `suspected` 타겟 생성

원본 데이터에는 “의심 차량”이라는 단일 정답 컬럼이 없기 때문에, 여러 위험 신호를 조합해 `suspected` 타겟을 만들었습니다.

의심 차량으로 판단한 기준은 다음과 같습니다.

- `frame_damaged`, `salvage`, `theft_title` 중 하나라도 있으면 중대 위험 차량으로 판단
- `has_accidents`가 있고, 인증 중고차나 CPO가 아니면 추가 확인이 필요한 차량으로 판단
- 신차(`is_new`)인데 사고 이력 또는 중대 위험 이력이 있으면 데이터 이상 또는 특이 케이스로 판단

이렇게 타겟을 만든 이유는 실제 서비스에서 “의심 차량”은 단순 사고 여부보다 넓은 개념이기 때문입니다. 사고 이력이 있어도 인증 절차를 거친 차량과 그렇지 않은 차량은 사용자에게 전달해야 하는 위험 수준이 다릅니다.

### 6. 최종 모델링 데이터 `df_model.csv` 생성

전처리가 끝난 피처와 새로 만든 `suspected` 타겟을 합쳐 최종 모델링 데이터인 `df_model.csv`를 만들었습니다.

최종 데이터에는 다음 컬럼이 포함됩니다.

- `mileage`
- `owner_count`
- `daysonmarket`
- `price`
- `savings_amount`
- `engine_type`
- `fuel_type`
- `body_type`
- `wheel_system`
- `transmission`
- `city`
- `seller_rating`
- `franchise_dealer`
- `suspected`

`has_accidents`, `frame_damaged`, `salvage`, `theft_title`은 `suspected`를 만드는 데 사용했지만, 최종 학습 피처에서는 제거했습니다. 이 컬럼들을 그대로 넣으면 모델이 정답 생성 규칙을 직접 보는 것과 같아 데이터 누수가 발생할 수 있기 때문입니다.

### 7. Logistic Regression 기준 모델 학습

먼저 Scikit-learn의 Logistic Regression을 기준 모델로 사용했습니다.

카테고리형 변수에는 One-Hot Encoding을 적용하고, 수치형 변수에는 StandardScaler를 적용했습니다. 또한 의심 차량 데이터가 정상 차량보다 적기 때문에 `class_weight="balanced"`를 사용해 클래스 불균형을 보정했습니다.

Logistic Regression을 먼저 사용한 이유는 단순하고 해석이 쉬워, 이 데이터로 의심 차량 예측이 가능한지 확인하는 기준선 역할을 하기 때문입니다.

### 8. PyTorch 기반 Tabular DNN 모델 학습

기준 모델 이후에는 PyTorch 기반의 Tabular DNN 모델을 학습했습니다.

DNN 모델에서는 카테고리형 변수를 embedding layer로 변환하고, 수치형 변수와 결합한 뒤 MLP 구조로 분류를 수행했습니다. 모델 구조는 hidden layer `(256, 128)`, dropout `0.3`을 사용했습니다.

DNN을 추가로 사용한 이유는 중고차 데이터가 수치형 변수와 카테고리형 변수가 섞인 표 형태 데이터이고, 도시·차종·연료 타입·구동 방식 같은 카테고리 조합이 의심 차량 여부와 복합적으로 연결될 수 있기 때문입니다.

### 9. Threshold 비교 및 최종 기준 선택

모델은 의심 차량일 확률을 출력합니다. 이 확률이 특정 threshold 이상이면 `suspected=1`로 예측합니다.

분석에서는 threshold를 `0.5`, `0.6`, `0.7`, `0.8`, `0.9`로 바꿔가며 precision과 recall 변화를 확인했습니다.

의심 차량 탐지에서는 두 지표를 함께 봐야 합니다.

- recall이 낮으면 실제 위험 차량을 놓칠 수 있습니다.
- precision이 낮으면 정상 차량을 과도하게 의심 차량으로 표시할 수 있습니다.

최종 threshold는 `0.6`으로 선택했습니다. 0.5보다 오탐을 줄이면서도, 의심 차량을 놓치지 않는 성격을 비교적 유지하는 균형점으로 판단했기 때문입니다.

### 10. 모델과 전처리 객체 저장

학습이 끝난 뒤 실제 추론에 필요한 파일들을 저장했습니다.

- 수치형 변수 정규화 기준: `scaler_juyeong.pkl`
- 카테고리 인코딩 기준: `cat_mapping.pkl`
- 모델 구조 및 컬럼 설정: `model_config.pkl`
- 학습된 모델 가중치: `weights_005_0.38692.pth`

서비스에서 모델을 사용하려면 학습 때와 동일한 전처리 기준이 필요합니다. 따라서 모델 가중치뿐 아니라 scaler, 카테고리 매핑, 모델 설정을 함께 저장했습니다.

### 11. 추론 코드 구성

`py/inference.py`의 `SuspectedCarPredictor` 클래스를 통해 신규 매물 데이터에 대해 의심 확률과 예측 결과를 반환할 수 있도록 구성했습니다.

이를 통해 분석 노트북에서 끝나는 프로젝트가 아니라, 실제 서비스나 다른 코드에서 재사용 가능한 예측 모듈 형태로 확장할 수 있습니다.

## 파일별 역할

### `used_car_suspicion_prediction.ipynb`

전체 분석 과정을 담은 메인 노트북입니다. 데이터 로드, 피처 선택, 결측치 처리, `suspected` 타겟 생성, 머신러닝 기준 모델 학습, DNN 모델 학습, threshold 비교, 최종 파일 저장까지의 흐름을 포함합니다.

### `df_model.csv`

전처리가 완료된 최종 모델링용 데이터입니다. 원본 데이터에서 서비스 목적에 맞는 피처만 남기고, 새롭게 정의한 `suspected` 타겟을 결합한 학습 데이터입니다.

### `py/tabular_dnn.py`

PyTorch 기반 Tabular DNN 모델 구조를 정의한 파일입니다. 카테고리형 변수는 embedding으로 변환하고, 수치형 변수와 결합해 정상 차량과 의심 차량을 분류합니다.

### `py/util_func.py`

모델 학습, 평가, 예측 결과 확인, 학습 곡선 시각화에 필요한 공통 함수들을 모아둔 유틸리티 파일입니다. 반복되는 학습·검증 코드를 함수화해 노트북의 흐름을 더 읽기 쉽게 만듭니다.

### `py/inference.py`

학습된 모델을 실제 예측에 사용할 수 있도록 만든 추론 코드입니다. 저장된 모델 가중치, scaler, 카테고리 매핑, 모델 설정을 불러와 신규 데이터에 대해 `suspected_prob`와 `suspected_pred`를 생성합니다.

### `pkl/scaler_juyeong.pkl`

수치형 변수 정규화에 사용한 StandardScaler 객체입니다. 학습 시점과 추론 시점의 수치 스케일을 동일하게 맞추기 위해 필요합니다.

### `pkl/cat_mapping.pkl`

카테고리형 변수의 값과 인덱스 매핑 정보를 저장한 파일입니다. 학습 때 사용한 카테고리 순서를 추론 시에도 동일하게 유지하기 위해 필요하며, 알 수 없는 값은 `__UNK__`로 처리합니다.

### `pkl/model_config.pkl`

모델 추론에 필요한 설정 정보를 저장한 파일입니다. 카테고리형 컬럼, 수치형 컬럼, 카테고리별 cardinality, hidden layer 구조, dropout, threshold 정보를 포함합니다.

### `pth/weights_005_0.38692.pth`

학습된 DNN 모델의 가중치 파일입니다. `TabularDNN` 구조에 이 가중치를 불러와 실제 예측을 수행합니다.

### `.gitignore`

Git에 포함하지 않을 파일이나 폴더를 정의하는 설정 파일입니다. 불필요한 임시 파일이나 환경 파일이 저장소에 올라가지 않도록 관리합니다.

### `README.md`

프로젝트의 목적, 분석 흐름, 파일별 역할, 기획 관점의 의사결정 이유를 설명하는 문서입니다.

## 다른 파일에서 사용할 때

```python
from inference import SuspectedCarPredictor
import pandas as pd

df = pd.read_csv("used_cars_data.csv").tail(3)

predictor = SuspectedCarPredictor(
    model_path="./weights_005_0.38692.pth",
    scaler_path="./scaler_juyeong.pkl",
    cat_mapping_path="./cat_mapping.pkl",
    config_path="./model_config.pkl"
)

result = predictor.predict(df, threshold=0.6)
print(result[["suspected_prob", "suspected_pred"]].head())
```

## 서비스 적용 아이디어

이 모델은 중고차 거래 플랫폼에서 다음과 같은 기능으로 확장할 수 있습니다.

- 매물 상세 페이지에서 “주의 확인 필요” 배지 표시
- 의심 확률이 높은 차량에 사고 이력 조회 CTA 제공
- 운영자 또는 검수 담당자의 리뷰 우선순위 산정
- 구매자에게 가격이 낮은 이유나 차량 이력을 추가 확인하도록 안내
- 플랫폼 내부 리스크 관리 대시보드 구축
- 판매자 신뢰도 관리 및 이상 매물 모니터링

단, 모델 결과는 법적 판정이나 절대적인 위험 판단으로 사용하기보다, 사용자가 추가 확인을 하도록 돕는 보조 신호로 활용하는 것이 적절합니다.

## 최종 인사이트

- 이 프로젝트에서 가장 중요한 점은 모델 성능 자체보다, 서비스 목적에 맞는 타겟을 정의하는 과정이었습니다.
- 원본 데이터에는 “의심 차량”이라는 정답이 없었기 때문에, 사고 이력·프레임 손상·salvage·도난 이력·인증 여부를 조합해 `suspected`를 직접 설계했습니다.
